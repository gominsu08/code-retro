# 개발 기록

## 2026-09-16 · 주제와 설계

공개 GitHub의 Unity 프로젝트를 시스템별로 이해하고 사용자의 코멘트로 포트폴리오 초안을 다듬는 도구로 정했다. 네임스페이스·스타일은 저작자를 확정할 수 없으므로 담당 후보와 사용자 확인을 분리했다. 짧은 요약보다 설계 선택·클래스·데이터·동작을 연결한 상세 문단을 유지하기로 했다.

구현 명세서는 AGENTS.md와 별도로 작성했다. UI는 어두운 개발 도구형으로, 시스템 목록·설명과 코드·코멘트의 3열 흐름을 적용했다.

## 2026-09-17 · 로컬 MVP 구현

React/TypeScript 화면과 FastAPI API, SQLAlchemy 저장 계층을 구현했다. SQLite로 로컬 작업을 보존하고 공개 운영을 위해 PostgreSQL 및 Alembic 구성도 준비했다. 분석 작업이 HTTP 응답을 오래 점유하지 않도록 별도 worker와 DB 큐를 사용했다.

GitHub의 branch/ref를 commit SHA로 고정하고 파일 원문의 Git blob SHA를 검증한다. 외부·생성 코드 제외 후보를 보여주고 선택된 C#만 읽는다. Tree-sitter로 선언 정보를 추출해 폴더 중심 시스템 초안을 만든다. 저장소에 포함된 코드를 실행하지 않는다.

AI는 범위가 제한된 읽기 도구 7개를 선택해서 호출한다. 도구가 발급한 근거와 선택된 코멘트 버전을 검사한 뒤 새 설명을 저장한다. 실패 시 원래 설명과 코멘트를 유지한다. 검토 완료 표시는 특정 설명·설정 버전에 연결한다.

## 실제 검증에서 수정한 문제

| 문제 | 원인과 조치 |
| --- | --- |
| 네이티브 모듈 실행 차단 | Windows Application Control에 걸린 conda 모듈 대신 실행 가능한 Python 기반 전용 venv를 사용했다. Vite는 지원되는 WASM 바인딩으로 빌드했다. 보안 설정은 바꾸지 않았다. |
| C# 네임스페이스 중복 | 파일 범위 namespace 처리를 수정하고 중첩 namespace·상속·필드를 검증했다. |
| 에셋 제공 코드가 기본 대상에 포함됨 | Bitgem·TutorialInfo·StarterAssets 경로를 외부 후보에 반영했다. 현재 샘플 기본 대상은 112개다. |
| 구형 Gemini 모델의 404 | 모델 목록에는 있어도 해당 계정에서 생성에 사용할 수 없었다. 실제 API 응답과 무료 요금 문서를 확인해 `gemini-3.5-flash-lite`로 바꿨다. |
| Gemini 도구 스키마의 400 | 메타데이터를 제거하며 실제 `title` 필드까지 지워졌다. 속성 이름을 보존하도록 수정하고 중첩 스키마 검사도 추가했다. |
| 수정 작업에서 기존 인용 거절 | 이전 설명의 코드 근거가 새 작업 발급 목록에 없었다. 같은 커밋·파일·줄·blob인지 재검증한 근거만 재사용하도록 수정했다. 실제 코멘트 반영 v3 생성이 성공했다. |
| 성공 후 AI 호출 통계 소실 | 완료 결과 저장 시 누적 사용 횟수를 유지하도록 수정했다. |
| 첫 생성의 불필요한 문맥 증가 | 긴 구문 분석 메모를 수정 대상 설명처럼 가져오는 경우가 있었다. 기존 AI 설명만 수정 문맥으로 제공하고 첫 생성은 실제 코드 본문을 읽도록 구분했다. |
| 취소했는데 재시도 문구가 남음 | 대기 작업 취소 시 이전 단계·오류를 지우고 취소 상태로 표시하도록 보완했다. |
| 모바일 가로 넘침 | 긴 경로·문단이 열 너비를 늘리지 않도록 최소 너비와 줄바꿈을 조정했다. 390px 검증을 통과했다. |

## 검증 결과와 남은 작업

자동 테스트 22개, Ruff, TypeScript/Vite 빌드가 통과했다. 실제 공개 저장소의 수집, 코멘트 저장, 새로고침 유지, 검토, Markdown 다운로드를 브라우저에서 확인했다. 실제 Gemini로 Machine 설명 생성 및 코멘트 반영도 성공했다. 네트워크·할당량에 따라 실제 API 결과와 문장은 달라질 수 있다.

Dockerfile과 무료 Render 웹 서비스 구성을 준비했다. 사용자가 먼저 로컬을 확인하기로 했으므로 계정 연결·공개 배포·GitHub 업로드는 진행하지 않았다. PostgreSQL과 Linux 컨테이너 실동작도 아직 검증 전이다.

이 기록은 개발·시험 기록이다. 사용자의 실사용 후기나 실제 프로젝트 개발 성과를 대신 작성한 내용이 아니다.
