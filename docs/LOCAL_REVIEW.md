# 로컬에서 먼저 확인하기

주소: [Code Retro 열기](http://127.0.0.1:8000/). 이 PC에서 서버가 실행 중일 때 접속할 수 있습니다.

## 첫 프로젝트

1. **저장소 연결**의 예시 버튼으로 아래 값을 채웁니다.
   - 저장소: `https://github.com/gominsu08/2025_Engine_TeamProject`
   - 내 GitHub 아이디: `gominsu08`
   - 유형: 팀 프로젝트
2. 저장소를 연결하면 파일 목록이 나타납니다. **프로젝트 코드만 선택**으로 범위를 확인합니다. 현재 샘플에서는 프로젝트 코드 112개가 기본 대상입니다.
3. 담당을 확인한 파일만 본인·공동·다른 참여자로 지정합니다. 모르겠다면 확인 필요 상태를 유지합니다.
4. **AI 상세 설명 함께 생성**을 끈 상태로 **시스템 분석 시작**을 누르면 우선 구조를 확인할 수 있습니다.

## Machine 설명 확인

왼쪽 목록에서 `Machine`을 찾고 **AI 설명 생성**을 누릅니다. 중앙에는 상세 설명, 오른쪽에는 코멘트 공간이 나타납니다. 코드 근거를 누르면 인용한 파일과 줄을 확인할 수 있습니다.

처음 합의한 “추상 클래스와 SO” 설명은 원하는 상세 수준의 예시입니다. 실제 저장소에 추상 클래스가 있다는 뜻은 아닙니다. 현재 샘플의 `Machine`은 `MonoBehaviour`를 상속하므로 설명도 실제 코드를 따라야 합니다.

다음은 **방향을 지정하는 코멘트 예시**입니다. 실제 개발 의도를 대신 작성한 문장은 아닙니다.

> Machine의 공통 동작과 Brazier의 개별 동작을 더 자세히 풀어주세요. MachineSO의 설정이 어떤 코드에서 쓰이는지도 연결해서 설명해주세요. 확인되지 않은 담당 여부나 성능 수치는 단정하지 말아주세요.

코멘트를 저장하고 선택한 뒤 **선택한 코멘트 반영**를 누릅니다. 버전 목록에서 수정 전후를 비교하고 실제 경험과 맞는지 확인합니다. 저장한 코멘트와 설명은 새로고침해도 남습니다.

## 내보내기

검토한 최신 설명에 검토 완료를 표시한 다음 **내보내기**로 이동합니다. 시스템을 선택하고 문서를 만든 뒤 Markdown을 다운로드합니다. 검토 전 내용을 보고 싶으면 **미검토 설명도 초안으로 포함**을 켭니다.

특히 볼 부분은 설명의 길이와 구체성, 시스템 분류, 코드 근거의 정확성, 코멘트 반영 정도입니다. 실제 담당 범위·의도는 직접 보완해야 합니다.

## 다시 실행하거나 문제가 생겼을 때

- 접속되지 않으면 README의 서버 실행 명령을 사용합니다. 터미널 창을 닫으면 로컬 서버도 종료될 수 있습니다.
- AI 키는 이미 이 PC의 `.env`에 설정했습니다. 키나 모델 설정을 바꿨다면 API와 worker를 함께 재시작합니다.
- 한도 안내가 나오면 저장된 설명·코드·코멘트를 먼저 확인합니다. 유료로 자동 전환하지 않습니다.
- GitHub 비로그인 조회 한도에 도달하면 새 저장소 확인은 대기할 수 있습니다. 이미 수집한 코드의 조회·AI 설명은 계속 사용할 수 있습니다. 이 경우 화면의 재조회 작업을 취소한 뒤 기존 시스템을 선택합니다.
- 다른 브라우저나 `localhost` 주소에서는 별도 작업 공간이 보일 수 있습니다. `127.0.0.1:8000`과 같은 브라우저를 계속 사용합니다.
- 공개 접속 URL은 로컬 검토 후 배포 단계에서 만듭니다.
